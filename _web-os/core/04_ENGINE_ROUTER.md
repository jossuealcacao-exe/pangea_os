# Router de motores

## Objetivo

Activar conocimiento bajo demanda para evitar instrucciones gigantes y contradictorias.

## Motores base

Siempre:
- Core OS.
- Intake.
- Clasificador.
- Arquitectura.
- QA proporcional.

## Activación condicional

| Señal | Motor |
|---|---|
| Dirección estética, UI, branding | `engines/design/` |
| Sitio o aplicación frontend | `engines/engineering/frontend.md` |
| Datos, auth, API, server | `engines/engineering/backend.md` |
| Shopify | `shopify/` |
| SEO, contenido indexable | `engines/discoverability/seo-geo.md` |
| Medición o CRO | `engines/discoverability/analytics.md` |
| Claims o tema especializado | `engines/research/` |
| Riesgo o datos sensibles | `engines/quality/security.md` |
| Handoff | `core/16_AHP_HANDOFF_PROTOCOL.md` |

## Estilos visuales

Selecciona un estilo dominante y, como máximo, un secundario. No cargues todos los estilos. Si el usuario no especifica uno, deriva una dirección de audiencia, contenido, marca y conversión.

## Conflictos

La regla más específica gana, salvo que contradiga seguridad, accesibilidad o hechos del repositorio.
